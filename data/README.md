# Dataset

**Default of Credit Card Clients**, UCI Machine Learning Repository (ID 350), licensed under
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

> Yeh, I. (2009). Default of Credit Card Clients [Dataset]. UCI Machine Learning Repository.
> https://doi.org/10.24432/C55S3H

The source URL, archive checksum and split parameters are recorded in
[`dataset-source.json`](dataset-source.json).

## Files

| Path | Origin | Contents |
|---|---|---|
| `dataset-source.json` | Committed | Source URL, SHA-256 of the original archive, split method and seed |
| `split-manifest.csv` | Committed | `ID,split` for all 30,000 records (`train`, `validation`, `test`) |
| `raw/` | Generated by `prepare` | Original downloaded archive |
| `features/validation.csv`, `features/test.csv` | Generated by `prepare` | `ID` + 19 model features. **No target, no demographics, no training records.** These are the only files the backend reads. |
| `restricted/{train,validation,test}.csv` | Generated by `prepare` | `ID` + 19 model features + target. Offline training and evaluation only. |

## Regenerating the files

From `ml-service/` with the virtual environment set up:

```
.venv\Scripts\python -m ml_service.data.prepare
```

The script downloads the archive if it is missing, stops if the checksum differs from
`dataset-source.json`, validates the schema, and writes the files above using the committed
`split-manifest.csv`. `--resplit` recreates the manifest from the seed instead; it is only
needed if the split definition itself changes.

## Split

Stratified by target with seed 42: train 70% (21,000), validation 15% (4,500), test 15% (4,500).
The default rate is 22.1% in every split. The split is made on the original records, before any
masking or preprocessing.

| Split | Used for |
|---|---|
| train | Model training only. Never served to acquisition sessions. |
| validation | Model selection, development sessions, debugging, policy tuning. |
| test | Final evaluation only, after model and policy decisions are fixed. |

## Notes on the data

- The `.xls` file has two header rows (`X1..X23, Y`, then the descriptive names); the second is used.
- There is no `PAY_1` column; the most recent repayment status is `PAY_0`.
- `PAY_*` contains the codes `-2`, `-1` and `0`, which are not described in the original
  documentation. They are kept as ordinal integers.
- No missing values; all columns are integers.
- 951 records share their 19-feature vector with at least one other record (134 distinct vectors).
  Most (783) are inactive accounts with all bill and payment amounts equal to zero. Labels differ
  within these groups, so they are different clients rather than copied rows, and they are kept.
- The demographic columns `SEX`, `EDUCATION`, `MARRIAGE` and `AGE` are excluded from the primary
  feature configuration (`config/feature-groups.json`) and from all generated files.
